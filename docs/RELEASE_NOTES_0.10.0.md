# LuWiki 0.10.0

0.10.0 は、[前段の 0.9.34 候補](RELEASE_NOTES_0.9.34.md)からの MCP・UI 改善に、
ページ状態取得と変更待ち、閲覧更新、テンプレート適用の修正、配信スキルと操作ボタンの改善を加えた版です。

## 非互換変更と既存利用者への影響

- `edit_page.operation`は1件でも非空配列で指定します。旧object形式は受理しません。
  section／anchorは呼出し開始時の本文を参照し、全操作成功後に一度保存します。
  新設した見出しや変更後の見出し名を使う場合は、保存後にTOCを再取得してください。
- `upload_page_asset`は`text`と`data_base64`をちょうど一方指定します。
  `text`は具体的な`text/*` MIMEとUTF-8に対応し、空文字も許可します。
  null、両方指定、空Base64は受理しません。前後空白・改行・BOMは保持します。
  raw上限10MiBと、JSON escape等を含む`/mcp`本文上限64MiBを区別してください。
- 新しいブラウザ資材は共通`/ws`と`type`／`payload`を使用します。
  本体更新後は通常リロードで新資材を取得してください。新旧wireの恒久共存は保証しません。
- テンプレート適用時は、front matter除去・即時マクロ処理の後に先頭空行をすべて除去します。
  LF／CRLF、半角スペース・タブだけの行を含み、空白だけの本文は空文字になります。
  非空行の字下げ、本文内部・末尾・コード内の空白は保持します。
  保存済みページの原文を一括変換する変更ではありません。

## ページ状態取得・変更待ち

`get_page_state`で既知の単一pathの状態を取得し、返された不透明な`state_token`を
`wait_page_change.expected_state`へそのまま渡します。本文・内部IDは取得しません。

```json
{"path":"/example","expected_state":"<get_page_stateのstate_token>","timeout_seconds":30}
```

1回の待機は整数1〜30秒、省略時30秒です。正常な`timeout`では同じ基準tokenを
保持して再待機できます。通常更新・amendは`updated`、同じpathの別ページは
`replaced`、削除・rename等で元pathを取得できなくなれば`unavailable`です。
`unavailable`から未公開の移動先を推測せず、必要な本文は別途`get_page`で取得してください。
初期未存在pathの作成待ち、全中間イベント・回数・履歴の配送は提供しません。
待機中も現在のBearer scope／prefix／期限を再確認し、tokenの寿命を延長しません。
`get_page`等の権限を待機toolの利用可否から推測しないでください。

## 閲覧更新と読書位置

- 通常の閲覧画面で、ページ変更時の動作を自動・半自動・無視から選べます。
  既定は半自動です。同じoriginで設定を保存し、別tabにも反映します。
- 自動は通常リロード、半自動は通知内の「更新」で最新本文を取得します。
  無視では購読・通知・自動更新を行いません。
- 削除・renameでは本文を保持し、現在の認可で案内できる移動先または通常先祖を示します。
  自動モードでも削除を理由に編集画面へ自動転送しません。
- 同じpath・同じIDの更新と通常リロードで、内容、見出し、保存スクロール量の順に
  読書位置を復元します。明示hash・画像／Mermaid描画・利用者操作との優先順位を扱います。
- ブラウザの「戻る」「進む」でページを再読込する場合も、履歴エントリに保存した閲覧位置を
  本文の描画後に復元します。同じ URL を複数回訪れた場合もエントリごとに位置を保持します。
- MCP無効起動、ReadOnlyでもブラウザの参照機能を利用できます。
  通知によるエージェントの自動起動は今回の機能に含めません。

## MCP で配信する運用指示と仕様書

- 運用指示本文を `luwiki://<authority>/builtin/agent-skill` から取得できます。
  リソースの読み取りが利用できない場合は、同じ接続先の `get_agent_instructions` を呼びます。
  両経路は同じ Markdown を返し、Bearer の `read` スコープを要求します。
- ローカルの `SKILL.md` には、導入時に接続先の具体的な URI を設定します。既定の
  authority は `local.luwiki` です。全文を配置する従来の導入手順からの移行方法は
  [スキルの設定](../SKILL_SETUP.md)を参照してください。配信本文には質問書への回答を
  `wait_page_change` で待ち、必要な回答を確認して作業を再開する例を追加しました。
- 既存の `front-matter-spec` と `mcp-prompt-spec` は同じ URI と一覧メタデータで、
  リポジトリを参照せずに使える配信用文書を返します。開発向けの正本は `docs/` にあります。
- ソース内の初期ページ・サンプルを `data/` から `assets/` へ移しました。
  MCP 配信用本文も同ディレクトリ配下に置き、実行ファイルに内包します。

## コードフェンスと Mermaid

- 操作ボタンをコードフェンスの右上に重ね、マウス操作では右上のボタン領域への
  ホバーまたはキーボードフォーカスで表示します。ホバーのない端末では常時表示します。
  機能名はホバー・フォーカス時に、コピー成功は「コピーしました」のポップアップで表示します。
- 描画に成功した Mermaid では拡大表示・全画面・コピーを横並びにします。
  コピーは通常のコードフェンスと同じ右端に揃え、描画に失敗した場合も元のコードをコピーできます。

## 前段から含む改善

- `{{mcp:authority}}`を表示・ページ由来resource・prompt元本文で展開します。
  保存sourceとraw取得は保持し、挿入引数値は再展開しません。
- 検索取得結果のpath部分一致filter、コード／Mermaidのコピー、長path一覧表示を改善しました。
- MCP保存成功後に全文索引を同期します。同期失敗時は保存済み正本を維持して
  固定`internal_error`を返すため、未保存と推測せず最新本文を再取得してください。
  過去の未索引データを自動再構築する変更は含みません。

## 更新・再接続・配布手順

1. 公開対象のソース、依存ロック、資材、版、検証記録とライセンスを確認します。
2. ソースからビルドするときは[ビルド手順](../README.md#リリースビルド)に従い、フロントエンドを先に
   生成し、`cargo build --release --locked` で内包します。Octicons のライセンスも同梱します。
3. 利用環境の更新担当者がバックアップ等の既存運用に従い、サーバを正常停止してから
   バイナリを置換・再起動します。同一DBを別processで同時操作しません。
   正常停止では監視・待機取消、監査確定、資源解放、最終flushの順を維持します。
4. MCP利用時は`run --mcp=true`等、[CLI仕様](CLI_SPECS.md)に従って有効化します。
   MCPはBearer認証を使用し、必要scopeとpath prefixを用意します。
   ブラウザのBasic認証をMCP入口へ流用しません。
5. サーバ再起動後はMCPセッションを初期化し直し、実際の`tools/list`を確認します。
   ブラウザは通常リロードで新しいHTML／JSを取得します。
   authority設定変更も再起動・HTML再取得／MCP再接続が必要です。
6. 従来の全文版を利用している場合は、サーバ更新後に
   [スキルの設定](../SKILL_SETUP.md)に従って短い `SKILL.md` へ差し替えます。
   設定した URI から運用指示を取得できることを確認します。
